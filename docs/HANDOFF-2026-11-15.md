## 0. Live PingOne MCP sign-in: what works and why (measured 2026-11-15)

- **The hosted PingOne MCP takes a user sign-in, never a worker token** (owner statement; Ping's early-access docs, [authentication](https://developer.pingidentity.com/build-with-ai/pingone-mcp-server/p1-authentication.html) and [client configuration](https://developer.pingidentity.com/build-with-ai/pingone-mcp-server/p1-client-configuration.html), document only an administrator signing in; the tools listed depend on that user's admin roles). The worker path is gone (#36).
- **Endpoint:** `https://mcp.pingone.<region>/admin/<envId>/mcp` (the `mcp-host` style, now the default). Its protected-resource metadata (`/.well-known/oauth-protected-resource/admin/<envId>/mcp`) names the issuer `https://auth.pingone.<region>/<envId>/as`, the MCP URL as the resource, and `scopes_supported: []`. The lab sends `resource=<MCP URL>` (RFC 8707) on authorize, code and refresh.
- **The working application:** the environment's existing public OIDC app named **"PingOne MCP Server"**. It has token auth None, authorization code + refresh, and PKCE S256 required. The saved connection **"PingOne hosted MCP (pi.flow)"** holds its client id; the id is not in this repo. The lab drives pi.flow with that app.
- **Redirect URI:** pi.flow still sends a `redirect_uri`, and it must be one the app registers. The connection uses `http://127.0.0.1:7474/callback`; nothing is served there, because pi.flow never redirects. The lab's placeholder `http://localhost/mfa-admin-mcp-lab/pi-flow` is refused (400 INVALID_DATA) by an app that does not register it. If a browser ever lands on it, the 404 is expected, and something other than the lab did a browser redirect.
- **What does not work:** Ping's universal client `pingone-mcp-server` (the one the docs give Claude Code, VS Code and Cursor) refuses pi.flow with `400 "Invalid response_mode for adminui"`. It allows only a browser redirect, which rule 16 forbids. The lab's earlier own sign-in app gave only 2 tools (`listRoles`, `getRole`), and the old confidential "Demo AI App - Admin Login" cannot do pi.flow at all; that card was deleted.
- **Login hint:** the pi.flow card has `loginHint = demouser` (#35). The dialog opens with it pre-filled.
- **Tokens live in memory only,** so every container recreate signs the owner out. Sign in again on the pi.flow card.

## 3. Recorded fixtures (PR #29) — how it works

- **Record:** Live connection (Banking/OpenSearch/PingOne) → call a tool → **"Record as fixture"** button on the CallView (Tool page + Raw console). POST `/api/fixtures` `{ tool, result, connectionId }`.
- **Storage:** `<data dir>/fixtures.json`, mode 600, secrets scrubbed via `redact.js` before write.
- **Replay:** mock demo answers a recorded tool with the real result verbatim + `_meta.recordedFrom` / `_meta.recordedAt`. Gate admits fixture-backed tools as **read-only**.
- **Manage:** `GET /api/fixtures`, `DELETE /api/fixtures/:tool`. `GET` currently shows `count: 0` — nothing recorded yet.
- Tests: `server/test/fixtures.test.js` (record/list/replay/delete + secret-scrub assertions).

## 3b. Recorded tool lists + synthetic replies (PR #31)

- **Record:** a Live connection's Tools page → **"Record this tool list for the mock demo"** → `POST /api/connections/:id/record-tools`. It saves names, descriptions, argument schemas and annotations from `tools/list`, and calls no tool. It is refused on the mock connection.
- **Storage:** `<data dir>/recorded-tools.json`, mode 600, merged by tool name, secrets scrubbed. Names outside `[A-Za-z0-9_.-]{1,128}` and schemas over 20 kB are skipped; 500-tool cap.
- **Mock demo:** lists the recorded tools with their normal safety class (a delete stays destructive and gated; a viewer sees only the read ones). A sample-catalog name keeps the catalog tool. Each answers with an invented record marked `synthetic: true` (a `list*`/`search*`/`find*` tool gets `items`). **A recorded fixture wins** over the synthetic reply. `purgeUserData` and `syncTenantWidgets` give the same synthetic record instead of a bare "ok".
- **Manage:** `GET /api/recorded-tools`, `DELETE /api/recorded-tools` (also "Forget recorded tools" on the mock demo's Tools page). Nothing recorded yet.
- Tests: `server/test/recorded-tools.test.js` (7), plus 3 in `web/src/App.test.jsx`.

## 4. Recurring operational traps (hit today, all overcame)

1. **lab-proxy loses lab networks** whenever the lab container is force-recreated: proxy serves 502 while the lab itself is healthy. Fix: `docker restart lab-proxy-lab-proxy-1` (watchdog also heals within ~5 min).
2. **Stale container after merge** — `docker compose up -d` says "Running" without rebuilding. Always use `--build --force-recreate` after merging, and verify the bundle actually contains the new feature (`docker exec <c> grep -c "<feature string>" /app/web/dist/assets/index-*.js`).
3. **Banking MCP token expiry** — the `banking` preset mints a 24 h test token. `MCP HTTP 401 -32001 "Token expired"` ⇒ delete + re-add via "Add banking MCP". Also `banking-mcp-resource-server` container must be running (`docker start banking-mcp-resource-server`).
4. **The lab proxy hides 502/503/504 bodies** (`error_page … proxy_intercept_errors on`). The lab answers upstream failures with 424 since #40. Any new upstream error path must not use 5xx.
5. **zsh `$VAR:u` is the uppercase modifier:** `"$I:user-login"` becomes `MFA-…SER-LOGIN`. Write `"${I}:tag"` when tagging images.
6. **Focused redeploy without the shared checkout:** `git archive <sha>` into a scratch dir, `docker --context air buildx build -t <image>:<tag> --load <dir>`, `docker --context air save … | docker --context orbstack load`, tag `:latest`, then `HOST_PORT=7815 docker compose -f <dir>/docker-compose.yml --project-directory ~/Development/mfa-admin-mcp-LAB up -d --no-build --force-recreate`. Tag the old image as the rollback first. Before replacing, check whether another session redeployed (`docker inspect … .Image`).
7. **e2e flake root-caused and fixed** (in #29): the Raw page's async `fillFromTools()` clobbered the test's params; e2e now waits for the fill status note. Plus a late connections-list wait. 3× clean since.
